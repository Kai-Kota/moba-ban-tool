# moba-ban-tool

MOBA の BAN/PICK を OBS の配信画面に重ねて表示するオーバーレイツールです。
ゲームの API は使わず、オペレーターが操作パネルから手動で入力します。

- キャラ一覧とドラフト順は JSON と画像で差し替えられるので、タイトルを問わず使えます
- サーバーは Windows 用の単一 exe(フロントエンドを埋め込み済み)です
- 操作パネルとオーバーレイは WebSocket で同期し、状態は `state.json` に保存されるので、再起動しても続きから再開できます

---

## 使い方(配布版)

### 1. 起動

配布フォルダの構成:

```
moba-ban-tool\
├─ moba-ban-tool.exe
├─ data\
│  ├─ characters.json
│  ├─ draft_order.json
│  ├─ images\        キャラ画像
│  └─ logos\         チームロゴ
└─ README.md
```

`moba-ban-tool.exe` をダブルクリックすると、コンソールウィンドウが開き、ブラウザで操作パネルが開きます。

```
  操作パネル  http://127.0.0.1:8080/control
  OBS 用      http://127.0.0.1:8080/overlay   (ブラウザソース 1920x1080)
```

- 終了するときはコンソールウィンドウを閉じます
- 初回起動時に Windows Defender SmartScreen の警告が出ることがあります。「詳細情報」→「実行」で起動できます
- ファイアウォールの許可を求められた場合、同じ PC だけで使うなら許可しなくても動きます

### 2. OBS の設定

1. OBS の「ソース」で **＋** →「ブラウザ」を選び、名前を付けて OK
2. プロパティを次のように設定します

   | 項目 | 値 |
   |---|---|
   | URL | `http://127.0.0.1:8080/overlay` |
   | 幅 | `1920` |
   | 高さ | `1080` |
   | カスタム CSS | 既定のまま(`body { background-color: rgba(0, 0, 0, 0); ... }`) |
   | 表示されていないときにソースをシャットダウン | **オフ** を推奨 |
   | シーンがアクティブになったときにブラウザの表示を更新 | どちらでも可 |

3. ソースをゲーム画面より上に置きます。背景は透過で、画面下部にドラフトのパネルだけが表示されます

- キャンバスが 1920x1080 でない場合も、ソースを右クリック →「変形」→「画面に合わせる」で合わせられます
- サーバーを後から起動したり再起動したりしても、オーバーレイは自動で再接続します
- 画像やロゴを差し替えた後は、ソースのプロパティで「現在のページのキャッシュを更新」を押してください

### 操作パネルを OBS の中に置く(カスタムブラウザドック)

ブラウザを別に開かず、OBS のウィンドウ内で操作できます。

1. メニュー「ドック」→「カスタムブラウザドック」
2. ドック名に `Draft Control`、URL に `http://127.0.0.1:8080/control` を入れて「適用」
3. 追加されたドックをドラッグして好きな位置に置くか、右上のボタンで別ウィンドウにします

- 幅が 1200px 未満のときは、キャラ一覧を上、両チームのボードをその下に並べた縦長レイアウトになります。チーム情報・試合情報は「▶ チーム情報・試合情報」を押すと開きます
- exe を更新した後は、ドック内で右クリック →「再読み込み」を押してください

### 3. 操作パネル(/control)

| 場所 | 内容 |
|---|---|
| 上部 | 接続状態、現在のステップ(どちらの BAN/PICK か)と次のステップ、Undo / 次の試合 / サイド入替 / リセット |
| 左右 | 各チームの BAN/PICK 枠。次に埋まる枠が光ります |
| 中央 | キャラ一覧。検索で絞り込めます。ピック・BAN 済みのキャラは選べません |
| 下部 | チーム名・ロゴ・コーチ・選手名の編集、勝利数、BO 形式、パッチ |

**キャラの確定**

- クリックで「選択中」になり、オーバーレイの該当枠で点滅します
- もう一度クリックするか Enter で確定し、次のステップへ進みます
- 「1クリックで確定」をオンにすると、クリックですぐ確定します

**ショートカット**

| キー | 動作 |
|---|---|
| `/` | 検索欄へ移動 |
| `Enter` | 選択中のキャラを確定(選択中がなければ、検索結果の先頭を選択中にする) |
| `Esc` | 選択中を解除、検索をクリア |
| `Ctrl+Z` | 1手戻す |

チーム名などの入力欄にカーソルがあるときは、ショートカットは効きません(検索欄は例外)。

**ボタン**

| ボタン | 動作 |
|---|---|
| Undo | 最後に確定した BAN/PICK を1つ取り消します。チーム情報の変更は戻りません |
| 次の試合 | ドラフトだけをクリアします。チーム情報と勝利数は残ります |
| サイド入替 | 青と赤のチーム情報(名前・ロゴ・コーチ・選手・勝利数)を入れ替えます。ドラフト開始前のみ |
| リセット | チーム情報も含めてすべて初期化します |

**チーム情報**

- 入力してから「反映」を押すとオーバーレイに出ます(入力中の文字は送られません)
- 勝利数の −/＋ は押した時点で反映されます
- ロゴは `data\logos\` に画像を置き、↻ を押すと選択肢に出ます

**試合の進め方の例**

1. チーム情報・BO 形式・パッチを入力して反映
2. ドラフトを進める
3. 試合が終わったら勝利数を ＋
4. 「次の試合」でドラフトをクリア。必要なら「サイド入替」

## 別タイトル用に差し替える

`data\` フォルダの中身を差し替えて exe を再起動するだけで使えます。コードの変更は不要です。

### characters.json

```json
[
  { "id": "aldric", "name": "Aldric", "image": "aldric.png" },
  { "id": "brynn",  "name": "ブリン",  "image": "brynn.png" }
]
```

| キー | 内容 |
|---|---|
| `id` | 一意な ID(英数字推奨)。`state.json` にはこの ID が保存されます |
| `name` | 表示名。日本語も使えます。操作パネルの検索は `name` と `id` の両方に一致します |
| `image` | `data\images\` からの相対パス。png / jpg / webp / svg など |

画像は縦長(9:16 前後)を推奨します。ピック枠では縦長のまま、BAN 枠と操作パネルでは中央やや上を正方形に切り抜いて表示します。

### draft_order.json

BAN/PICK の順番を、1手ずつ並べます。

```json
[
  { "team": "blue", "type": "ban",  "label": "Ban Phase 1" },
  { "team": "red",  "type": "ban",  "label": "Ban Phase 1" },
  { "team": "blue", "type": "pick", "label": "Pick Phase 1" }
]
```

| キー | 内容 |
|---|---|
| `team` | `blue` か `red` |
| `type` | `ban` か `pick` |
| `label` | 省略可。オーバーレイ中央のフェーズ表示に使います。BAN 枠は label が変わるところで区切って表示されます |

- 1チームのピックは最大5回です。BAN の数に制限はありません
- 同梱の設定は、BAN 3 → PICK 3 → BAN 2 → PICK 2 の大会形式(計20手)です
- `draft_order.json` を変えて起動すると、枠数が合わなくなった保存済みのドラフトは自動でクリアされます

### 起動時のエラー

設定ファイルに問題があると、起動時にエラー内容を表示して止まります(ID の重複、`team` / `type` の誤り、ピックが5回を超えるなど)。
画像ファイルが見つからない場合は警告だけ出して起動します。

## 起動オプション

コマンドプロンプトや PowerShell から指定できます。

```
moba-ban-tool.exe -addr 0.0.0.0:8080 -data D:\overlay\data
```

| オプション | 既定値 | 内容 |
|---|---|---|
| `-addr` | `127.0.0.1:8080` | 待ち受けアドレス |
| `-data` | カレントの `data`、なければ exe の隣の `data` | 設定と画像のフォルダ |
| `-state` | `data` フォルダと同じ場所の `state.json` | 状態の保存先 |
| `-open` | `true` | 起動時にブラウザで操作パネルを開く。`-open=false` で無効 |

### 別の PC から操作する

配信 PC で `-addr 0.0.0.0:8080` を付けて起動し、操作用 PC のブラウザで `http://<配信PCのIPアドレス>:8080/control` を開きます。
Windows ファイアウォールでの許可が必要です。同じネットワークの誰でも操作できるようになるので、信頼できるネットワークでのみ使ってください。

## 開発

### 必要なもの

- Go 1.25 以上
- Node.js 22 以上

### 開発サーバー

ターミナルを2つ使います。どちらもリポジトリのルートで実行します。

```
go run ./cmd/draftserver
```

```
npm --prefix web install
npm --prefix web run dev
```

http://localhost:5173/control と http://localhost:5173/overlay を開きます。
Vite の dev server が `/ws` `/api` `/assets` を Go サーバー(:8080)へプロキシします。

- `go run` で起動したサーバーはフロントエンドを埋め込んでいません。:8080 を直接開くと案内ページが出ます
- オーバーレイを通常のブラウザで開くと、背景が市松模様になり、画面に収まるよう縮小されます(OBS 内では透過・等倍)。`?preview=0` / `?preview=1` で切り替えられます
- npm のプロキシ設定(`npm config get proxy`)が今のネットワークで使えない場合は、`npm install --proxy=null --https-proxy=null` のように一時的に無効にしてください

### テスト

```
go test ./...
npm --prefix web run typecheck
```

### 配布用ビルド

```
powershell -ExecutionPolicy Bypass -File scripts\build.ps1
```

`release\moba-ban-tool\`(exe・data・README)と `release\moba-ban-tool.zip` ができます。
exe は `go build -tags embed` でビルドされ、`web\dist` の中身を埋め込みます。

### ダミーデータの生成

```
go run ./scripts/genplaceholders
```

20体のダミーキャラ(`characters.json` と SVG 画像)とロゴ2つを `data\` に生成します。`characters.json` を上書きするので、本番データのフォルダでは実行しないでください。

### 構成

```
cmd/draftserver/      エントリーポイント(フラグ、data の探索、起動)
internal/draft/       DraftState と更新ルール(BAN/PICK、Undo など)。テストあり
internal/config/      characters.json / draft_order.json の読み込みと検証
internal/store/       state.json の保存と復元
internal/hub/         WebSocket 接続の管理と配信
internal/server/      HTTP ルーティング
web/                  フロントエンド(Vite + React + TypeScript)
  src/shared/         Go と対応する型、WebSocket フック
  src/control/        操作パネル
  src/overlay/        オーバーレイ
  embed.go            -tags embed のときに dist を埋め込む
data/                 キャラ・ドラフト順・画像(タイトルごとに差し替え)
scripts/              ビルドスクリプト、ダミーデータ生成
```

### 通信の仕組み

- サーバーは DraftState を1つだけ持ち、変更のたびに接続中の全クライアントへ丸ごと送ります(`{"type":"state","state":{...}}`)
- 操作パネルは操作を送ります(`{"type":"confirm","charId":"aldric"}` など)。サーバーが検証して state を更新し、配信します。検証に失敗した場合は、送ったクライアントにだけ `{"type":"error"}` が返ります
- 型は `internal/draft/types.go` と `web/src/shared/types.ts` の両方で定義しています。JSON のキーを変えるときは両方を揃えてください
